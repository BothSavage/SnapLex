## 5. 构建、数据隔离与实际限制

1. 正常构建入口是 `./scripts/build_app.sh`，打包结果 `dist/SnapLex.app`。基线运行 `swift test -c release` 并记录 Git SHA、未提交差异、构建时间及签名校验结果。
2. 使用 `mktemp -d "${TMPDIR%/}/snaplex-ui.XXXXXX"` 创建唯一 macOS 真实临时根。复制打包应用到该目录，使用专用 bundle ID（如 `io.github.snaplex.uitest.<runID>`）并重新本地签名，避免改动正式副本。
3. 启动临时副本可执行文件时设置 `SNAPLEX_ISOLATED_TEST_DATA_ROOT=<临时根>` 和 `SNAPLEX_SELECTION_TRACE=1`。不要猜测其他不存在的 GUI 故障注入开关。
4. 操作前确认该进程打开的 SQLite 路径位于临时根，且两类历史为空。目录内生成的所有数据和导出文件使用本轮 run ID。
5. `LocalTestDataPaths` 只接受解析后位于 `FileManager.default.temporaryDirectory` 下的子路径；无效显式路径会降级至统一 `SnapLex-Rejected-Test-Data`，不同失败测试可能共用该目录。更改 HOME 或直接猜测 `/tmp/foo` 不足以证明隔离（`Storage/LocalTestDataPaths.swift:6–29`）。
6. 环境变量只隔离翻译历史和截图存储。偏好使用 `UserDefaults.standard`，应通过独立 bundle ID 隔离；剪贴板、系统热键、TCC、登录启动未被这个变量隔离（`Models/Models.swift:186–274`）。
7. 日常实例和测试实例可能竞争同一全局热键。系统级用例前确认各实例归属及注册日志，不能将测试环境冲突直接判作产品缺陷。
8. 首次权限、权限撤销及登录启动需独立测试账户或虚拟机；不能重置日常权限制造状态。只有单屏时多屏场景保留未验证原因。
9. 固定日期、假翻译服务和故障响应在 XCTest 构造器里可注入；当前 GUI 没有完整通用注入入口。要测试确定性网络失败，应说明受控环境准备方式，未准备则未验证。
10. 手动翻译 `.manual` 不写历史。鼠标/快捷键/双复制受划词记录开关控制，截图 OCR 受截图记录开关控制；不能将“手动翻译后无历史”判失败（`Storage/TranslationHistoryStore.swift:104–113`）。

## 6. 现有自动测试与计划缺口

`TranslatorViewModelTests` 已覆盖空卡改目标、同源同目标、Google 成功、条输入路由、Google→Apple 回退、原生失败、旧 Google 响应失效；这些是依赖注入测试，不能证明真实菜单点击、系统语言下载界面、TTS 声音、窗口焦点或全局事件。

`NativeTranslationSupportTests.swift:60–96` 部分测试随系统支持和语言包跳过；跳过不能算桌面路径通过。`TranslationCardShortcutActionTests` 只证明 show/hide 纯决策。

现有 `docs/testing/desktop-test-plan.md` 与 `snaplex-regression-plan-zh.md` 已包含层级、视觉、20 轮与 30 分钟目标，但还需落地：

- 每个控件的出现状态和菜单子项清单；分别统计点击覆盖与行为断言覆盖。
- 条仅四按钮、源语言只读、手动翻译不记录的正确产品边界。

- 动态定位优先；角色/标题不足时读取当次截图后定位，坐标必须来源于当前画面。

## 7. 证据与完成标准

每个 case 保存：前置截图、动作、结果截图、样本 ID、起止时间、request ID、相关日志、窗口/进程状态、实际状态和失败/未验证原因。复制需粘贴验证，导出需文件存在与内容/格式验证，TTS 需音频证据；只点按钮不能记通过。

逐控件通过后才执行交叉场景与压力序列。发现问题先保存证据和最小复现，再清理本轮临时状态；禁止无证据反复点击把结果“试到成功”。测试报告应同时列出通过、失败、未验证和不适用数量，不得用单元测试数量代替桌面验收覆盖。
