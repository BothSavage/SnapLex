# SnapLex 测试与发布验收计划

日期：2026-10-25。本文是后续执行方案，不代表尚未建立的自动化已经可用。历史执行证据和测试库存见 [desktop-test-plan.md](desktop-test-plan.md)。

## 1. 当前问题与责任

现有测试偏重策略、状态和动作回调，不能证明完整界面可读、真实鼠标事件到达、系统权限窗口没有被遮挡。根视图尺寸正常、外观枚举映射正确、按钮回调执行一次，都不能单独证明用户操作成功。

开发方负责准备隔离样本、执行回归、检查截图和日志、修复失败项并出具结果。用户日常使用反馈是补充信息，不作为开发方的常规验收步骤。未经验证的关键路径必须明确保留，不能以单元测试数量或一次启动成功代替。

## 2. 测试入口与数据隔离

建立专用本地测试入口，允许注入临时数据目录、固定日期、语言、外观、假翻译服务和故障响应。普通启动保持生产行为；测试入口不得读取或清理真实历史、真实截图、日常剪贴板。

| 样本组 | 必备内容 |
|---|---|
| 文本 | 普通英文单词、蓝色链接、短句、多行、中英混合、空白、emoji、长词、极长段落；可编辑与只读文本分别准备 |
| 图像 | 横图、竖图、超宽图、透明图、空白图、已知主体、无主体、清晰二维码/条形码、无二维码、损坏或已删除的文件 |
| 翻译记录 | 空记录、1 条、数百条；重复词、忽略词、中文源文、英文源文、失败请求、跨日与月边界 |
| 截图记录 | 0/1/3/100/101 张；不同宽高比、图片加载失败、保留上限变更 |
| 服务响应 | 立即成功、延迟成功、超时、取消、断网、限流、空结果、格式错误、旧请求晚返回；Apple 语言不支持/语言包未就绪 |

每次运行使用唯一临时目录；测试结束只清理该目录。控件使用稳定标识定位；视觉证据只包含合成样本。当前禁止访问 GitHub、禁止向其他应用发送合成输入的限制继续生效。

## 3. 优先级按已发生的故障排序

| 优先级 | 必须覆盖的故障 | 核心断言与证据 |
|---|---|---|
| P0 | F1 权限死循环、截图覆盖层挡住系统询问 | 未授权时不展示拦截输入的覆盖层；允许/拒绝后均能恢复；每个状态都能取消 |
| P0 | 首次划词失败、反复弹窗、抢输入框 | 一次手势最多触发一次；当前选区准确；编辑区操作不弹窗；关闭后旧结果不能重新打开卡片；原输入焦点保留 |
| P0 | 截图、翻译或切页导致崩溃/卡住 | 操作完成后进程仍存活；主线程可响应；等待和失败状态有退出路径；有对应日志时间段 |
| P0 | 深色模式内容消失、主界面遮挡截图、Esc 无效 | 完整窗口文字可读；截图前窗口顺序正确；输入焦点在文字编辑器时 Esc 仍释放当前窗口 |
| P1 | 标注无法移动/缩放/旋转、连续绘制误拖外框 | 每种标注都执行创建→取消选择→再次命中→移动→缩放→旋转→撤销；新标注完成不自动留下调整框 |
| P1 | 多语言溢出、控件未对齐、缩略图越界 | 检查实际渲染截图和控件边界；长文案不截断关键操作；图片不覆盖相邻卡片 |
| P1 | 发音读成中文、释义挤成段落、卡片无限增高 | 朗读参数使用源词及源语言；释义分项；超过 10 个排版行后在内容区滚动；底部操作仍可见 |
| P1 | 中文误入词频、开关无效、统计不准、截图保留错误 | 已知样本的词条、频次、时间过滤和文件数量与预期一致；忽略词立即退出后续自动统计 |
| P1 | 关窗口导致后台退出、重新打开状态错误 | 关闭主窗口后状态栏和热键服务存活；重新打开可用；明确退出才结束进程 |

权限锁死、输入劫持、崩溃、数据丢失、完整窗口不可读属于发布阻塞项。

## 4. 四类验证各自承担什么

### A. 逻辑与服务测试

使用现有 XCTest、假服务、临时时钟和临时存储验证决策、错误恢复和数据结果。异步请求使用可控闸门：先发 A，再发 B，让 B 先完成、A 后完成，确认只显示 B。不得通过重复断言实现细节扩大测试数量。

### B. 完整界面渲染检查

渲染完整的状态栏面板、控制台五页、划词条、翻译卡片和标注工具栏；不能只检查根视图宽高。分别检查文字是否可读、内容是否裁切、按钮是否被遮住、底部操作是否在可见区域、缩略图是否越过卡片边界。

外观必须覆盖六种组合：系统浅色/深色 × 应用跟随系统/浅色/深色。尤其检查“系统浅色＋应用深色”和反向组合，并在窗口已经打开时切换、关闭重开、重启后再检查。原生窗口外观、SwiftUI 前景和背景必须一致。

语言先对简中、英文、德文做完整界面截图检查，再对其余支持语言做文案与溢出检查。窗口覆盖最小允许尺寸、默认尺寸和最大化；翻译卡片覆盖 1/10/11 行、超长释义和空结果。字体渲染差异允许小幅像素容差；大面积空白、丢字、裁切和重叠必须失败。首次视觉基线由开发方逐张检查，不能把当前缺陷直接当成正确基线。

### C. 真实窗口与完整操作链

在注入合成数据的 SnapLex 测试实例里，验证实际可见窗口、控件动作、焦点和文件结果：

1. 状态栏→截图入口→选区→标注→复制/保存→截图历史。
2. 测试选区数据→划词条→翻译卡片→切换引擎→朗读参数→记录→词频。
3. 控制台打开→启动截图→退出截图→回到控制台。
4. 翻译中关闭卡片→旧结果返回→卡片保持关闭；再打开能接受新请求。
5. 关主窗口→状态栏仍在→重新打开；输入编辑中按 Esc→窗口释放。

跨应用真实拖选、真实 TCC 权限弹窗和多屏事件，当前约束下仍有未验证部分。后续需要经授权的专用 macOS 测试环境补齐；自动化直接改变选区但没有全局 down/up 事件的结果不得计为划词端到端通过。该缺口由开发方记录和安排，不交给用户日常试用发现。

### D. 连续操作与性能检查

单次操作通过后，执行固定操作序列：切页→截图→Esc→打开翻译卡片→切引擎→关闭→再打开状态栏。先完成 20 轮可重复序列，再进行 30 分钟混合操作检查。记录随机序列种子以便重放。

冷启动和首次请求单列：不能用“预热后能用”替代首次划词、首次翻译、首次截图。检查等待中切页、关闭、再次发起请求、睡眠唤醒后的恢复，以及 0/100/1000 条合成记录下的表现。

下面是建议目标，尚非现有实测结果；首次用统一设备和测量方式建立基线后再确定阈值：

| 指标 | 建议初始目标 | 测量方式 |
|---|---|---|
| 热切页到目标页可见 | p95 ≤ 200 ms | 应用内记录点击与目标内容首次显示；自动化查询耗时另计 |
| 打开状态栏面板 | p95 ≤ 250 ms | 打开请求至面板可见 |
| Esc 释放当前窗口 | p95 ≤ 150 ms | 收到事件至窗口隐藏 |
| 鼠标松开到划词条出现 | p95 ≤ 500 ms | 仅接受实际全局事件的样本，不含翻译网络耗时 |
| 稳定性 | 规定序列内 0 崩溃、0 输入劫持、0 重复弹窗 | 操作日志、进程状态、可见窗口数量及脱敏诊断 |

## 5. 哪些时候执行哪些检查

| 时机 | 开发方执行 | 交付证据 |
|---|---|---|
| 修复一个 bug | 最短复现→针对性回归→受影响的完整操作链 | 复现与修复后的结果、对应测试或截图 |
| 改 UI/外观/语言 | 相关窗口的六种外观组合、长文案和最小尺寸 | 合成内容的前后截图；不能只给构建通过 |
| 改划词/窗口/快捷键 | 首次触发、重复触发、输入框保护、焦点、Esc、旧请求回调 | 事件及窗口证据；未覆盖的系统路径明确列出 |
| 改存储/统计 | 临时数据的读写、重启、时间边界、删除和保留上限 | 已知输入与结果对照 |
| 发布候选包 | 全部相关自动化、完整主要操作链、20 轮连续操作、打包签名、从最终包启动复验 | 构建身份、测试结果、关键界面证据、剩余阻塞项 |

日常小修按受影响范围验证；只有新改动、失败或未解决的疑点才扩大或重复测试。权限首次授权使用独立环境，不能撤销日常账户授权来制造场景。

## 6. 验收报告与发布门槛

每次结果只记录四种状态：通过、失败、未验证、不适用。不适用必须有原因；未验证不能自动算通过。

报告必须包含：源码版本/本地差异标识、打包时间和签名、macOS 与显示配置、测试数据来源、实际执行场景、失败截图或脱敏日志、未验证路径。总测试数量只能作为执行规模，不能作为质量结论。

发布候选包满足以下条件才可标记“验收完成”：

- 相关自动化和完整主要操作链通过，发布阻塞项为零。
- 外观、语言与最小尺寸的关键界面已看过实际渲染证据。
- 从最终 dist 包复验，而不是仅验证开发进程。
- 真实鼠标、权限和焦点等关键路径有实际证据；缺失时仅标记“本地修复完成，发布验收未完成”。

## 7. 优先落地顺序

1. **首先补隔离测试入口与视觉回归。** 固定六种外观组合、五个主页面和两类翻译浮窗，首先拦住深色白底、丢字、溢出与缩略图越界。
2. **再补核心操作链。** 优先划词首次失败/输入保护/关闭后不重弹、F1 权限与 Esc、文字标注重新选中，以及从最终包启动。
3. **然后补连续操作与性能基线。** 用固定序列覆盖状态残留和竞态，保存 p50/p95，针对实际回归设置阈值。

上述是待实施顺序，不是已完成清单。执行测试时发现的隔离缺口和本轮验证结果，记录在下方。
